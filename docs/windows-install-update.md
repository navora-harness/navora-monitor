# Windows 安装、系统服务与更新方案

适用版本：0.4.4，Windows x64。安装包与绿色版均内置 FFmpeg、ffprobe 和 Web 界面。

本次更新新增 1 大 3 小、1 大 5 小、1 大 7 小、1 大 12 小主辅布局，支持设为主画面和布局保存；实时预览增加首帧超时、画面停滞自动重连与手动重新加载。退出程序入口统一放在设置的关于页面。

0.4.4 修复时间轴相邻片段时间标签拥挤的问题，空间不足时减少标签显示；修复全屏状态下右键菜单不可见的问题。包含 0.4.2 的录像缓存选择、异常音频时间戳修复和 H.265 兼容回放改进。

0.4.4 优化时间轴区间查询与密集录像绘制，增加有界索引缓存、回放任务优先级和低优先级相邻片段预加载。多路实时预览使用后台线程，隐藏或放大的画面按实际观看需求释放。回放状态、失败恢复、保存结果和录像缺口反馈同时改进；沿用此前的配置、录像和认证数据。

配置 JSON 损坏或读取权限不足时，程序明确停止启动并指出文件名；不会以默认配置覆盖损坏文件。先备份原文件，再从已验证备份恢复，不要直接删除账户文件来处理升级故障。

同一数据目录只能由一个前台实例或服务占用，即使改成不同端口也不能同时运行。密码初始化和重置也需要先停止已有实例。目录中的 `.navora-instance.lock` 是保留的锁文件，进程退出或终止后系统自动释放占用，不必删除它。不同数据目录仍不能安全地共用同一录像或缓存目录，请为各实例分配独立存储目录。

## 首次正式安装

1. 运行 `NavoraMonitor-0.4.4-win-x64-setup.exe`，接受管理员权限提示。
2. 程序默认安装到 `C:\Program Files\Navora Monitor`。需要系统服务时保持“注册并启动系统服务”勾选。系统服务的程序必须放在 Program Files 内。
3. 配置默认存放在 `C:\ProgramData\Navora Monitor`，录像、已保存片段、截图、缓存分别存放在其中的子目录；可登录后在设置中换到录像专用磁盘。新数据目录授权 SYSTEM、管理员和服务账户 LocalService，普通用户不直接访问认证文件。
4. 安装结果窗口会显示首次生成的账户与密码，只显示一次，请立即保存。密码不会写入安装明细或安装日志。
5. 从开始菜单打开 Navora Monitor 浏览器入口。默认地址为 `http://127.0.0.1:8780/`，已有配置使用其他端口时快捷方式跟随该端口。

远程访问默认关闭。在设置中允许局域网设备访问并保存后，监听立即切换，无需重启服务或录像任务。端口或命令行监听地址变更仍需重启。0.3.44 起，安装和注册服务时自动创建或更新防火墙规则：仅允许本地子网访问本程序的配置端口，适用于所有网络配置文件。开关关闭时仍仅监听本机。修改端口后，需重新运行安装程序或下方修复操作以更新防火墙规则。

其他电脑应访问带实际端口的地址，例如 `http://192.168.31.36:8780/`，只输入 IP 会访问 80 端口。本机使用同一个局域网地址能打开、其他电脑超时时，可在部署主机的管理员 PowerShell 中运行：

```powershell
& 'C:\Program Files\Navora Monitor\windows-deploy.ps1' -Action AllowLanFirewall
```

此操作读取已注册服务的实际数据目录与配置端口，仅允许本地子网访问指定的 navora.exe TCP 端口，不关闭防火墙。跨子网访问需要管理员按网络范围另设规则；域策略中的拒绝规则或第三方安全软件可能仍会拦截。在访问端电脑执行 `Test-NetConnection 192.168.31.36 -Port 8780` 可检查端口连通性；应替换为实际配置端口。

## 旧配置与存储路径

- 升级沿用旧服务 `--data` 指定的数据目录；不会改读另一个 ProgramData 目录。相对数据路径无法可靠判断旧服务工作目录，安装明确拒绝并提示先确认绝对路径。替换程序前，在数据目录的 `config-backups/日期-唯一编号` 备份 settings.json、channels.json、auth.json、recording-session.json 和 layout.json（存在的文件）。备份包含认证信息，请保留在受保护目录。
- 已注册服务的 settings.json 缺失时，安装停止并明确提示，避免初始化新配置掩盖丢失。程序检测到 auth.json 或 channels.json 存在而 settings.json 缺失时也拒绝启动。新版不会找回已经删除且无备份的设置。
- 明确配置的录像、截图、保存片段、缓存路径及缓存开关完整保留。旧配置中的空路径会固定为数据目录下的 media 子目录；若旧账户默认目录已含内容，则保留并固定该旧路径，不移动或删除文件。
- 已有存储路径位于 Windows 系统目录时，界面持续提示。新设置禁止将存储指向 Windows 系统目录。请选择独立录像盘，并确保服务账户有写入权限；更换路径不搬迁旧录像或旧缓存。
- 设置 → 录像中可查看和编辑缓存开关、缓存目录；关闭缓存仍保留目录设置。默认缓存固定在数据目录下的 record-cache，不随服务账户变化。
- 录像或缓存目录、缓存开关修改前须先停止录像；保存后重新开始，避免旧 FFmpeg 继续写到已被新设置隐藏的目录。相对存储路径解析到实际数据目录并固定成绝对路径，不使用服务工作目录。

## 时间轴操作

实时和回放默认跟随时间滚动。拖动可浏览或定位；“恢复跟随”回到当前时间。滚轮连续缩放，Shift+滚轮或触控板横向滚动平移。跟随模式缩放保持中心播放时间，自由浏览时缩放保持鼠标指向的时间。缩放限制为一屏至少 5 秒、至多 7 天，超宽屏还受每秒 240 像素限制。刻度和录像块按可视范围绘制，长距离平移不会只留下最前面的刻度。

已保存时间轴独立保存日期、缩放与浏览位置，不被实时“现在”位置拉走。新保存片段立即建立实际媒体时长索引；旧片段分批补测，并显示读取状态。唯一文件名的时间戳会正确识别，跨午夜片段可在两天中查到。重叠片段分轨展示，可用片段选择框或直接点击指定文件；播放保留所选文件与起播位置。短片段适应视图不会强制扩大到三分钟。

未选择注册服务时，在管理员终端中运行：

```powershell
& 'C:\Program Files\Navora Monitor\navora.exe' --data 'C:\ProgramData\Navora Monitor'
```

## 系统服务操作

在管理员 PowerShell 中执行，服务名称固定为 `NavoraMonitor`。脚本会输出错误原因，并在失败时返回非零退出状态。

```powershell
$deploy = 'C:\Program Files\Navora Monitor\windows-deploy.ps1'
& $deploy -Action Register
& $deploy -Action Start
& $deploy -Action Stop
& $deploy -Action Remove
```

注册默认使用延迟自动启动；更新已有服务保留原启动策略。注册与启动分开操作。注册服务前先正常退出前台实例，避免同时争用数据目录和端口。移除服务保留配置、账户与所有录像。

新服务使用权限较低的 LocalService 账户；更新已有服务保留其原服务账户。换到其他磁盘时，需要给 LocalService（SID S-1-5-19）相应目录的修改权限。LocalService 不具备当前登录用户的网络共享身份，网络存储需另行配置受控服务账户与访问权限。服务模式下网页里的服务管理可能因非管理员权限受限，使用管理员部署脚本管理。

服务日志位于实际数据目录 `logs\service.log`，持续写入达到 4 MiB 时自动轮转，保留上一份 `service.log.1`。单条超大日志仅保留末尾；旧版本留下的超大日志首次轮转时完整保留为 `.1`，后续再轮转替换。启动失败时同时检查 Windows 服务状态和此日志；数据目录被其他实例占用时，服务会启动失败，先退出已有实例再重试。

忘记密码时先停止服务，再在管理员终端执行：

```powershell
& 'C:\Program Files\Navora Monitor\navora.exe' --data 'C:\ProgramData\Navora Monitor' --init-only --reset-password
```

随后启动服务。原账号与录像保留；新密码仅在本次终端中显示。

## 更新已安装版本

1. 导出配置，额外备份数据目录中的配置与认证文件。重要录像按自己的保留策略另行备份。更新程序不会复制整盘录像。
2. 核对发行包的 SHA-256，运行新版本安装程序，选择同一程序目录。
3. 安装程序先校验所有托管程序文件；检测已有服务时保留其 `--data` 路径。前台程序若仍运行会阻止更新，避免强制结束导致录像丢失。
4. 确认服务停止后，旧程序移入 `.rollback-<随机标识>` 备份目录，再复制新文件。既有数据目录中的录像、配置和账号不覆盖。
5. 原来运行的服务会恢复启动；原来停止的服务保持停止，除非明确勾选注册并启动。运行后检查本机状态接口的应用名和版本。
6. 替换、注册或健康检查失败时，尝试恢复旧程序和原服务路径，恢复原运行状态。失败信息会明确提示是否需要人工恢复。

安装结果中的备份路径应保留至真实摄像头录像、回放、导出验证通过。程序备份仅包含受安装程序管理的文件，不是录像或配置备份。版本回滚前先确认新旧版本数据格式兼容；0.4.4 沿用已有索引格式，派生播放缓存可重新生成，仍建议保留配置备份。

已初始化的默认数据目录支持静默更新 `/S`。首次安装必须使用交互模式以接收初始密码；不支持未初始化账户的静默首次安装。已有服务使用非默认数据目录时，优先交互更新。

## 绿色版与旧版迁移

绿色版解压到可写目录，运行 `navora.exe`；沿用同目录 `portable` 数据。升级绿色版前正常退出，先备份 `portable`，仅替换程序、媒体工具与说明文件，保留 `portable` 和实际录像路径。

旧安装器使用 `%LOCALAPPDATA%\Navora Monitor`，新正式安装器使用 Program Files。旧用户级安装记录不会被冒充为新系统级安装记录，也不会自动删除。

从绿色版或旧用户级安装迁移系统服务：

1. 停止旧服务/前台程序，导出配置并备份全部配置目录。
2. 将配置、认证、布局、录像恢复状态等复制到选定的独立数据目录，保持已有录像位置，核对路径与服务账户访问权限。不要把可写配置目录直接当成系统服务程序目录。
3. 先用新程序和 `--data <新数据目录>` 前台验证，再注册新服务。
4. 若已有服务的 `--data` 在程序安装目录内部，部署脚本会拒绝直接升级，需先迁移数据并调整服务路径。避免把用户数据误纳入程序备份或替换。

## 校验与人工恢复

绿色发行包内的 `manifest.json` 记录托管文件 SHA-256，可在不修改服务或系统的情况下验证：

```powershell
& .\windows-deploy.ps1 -Action Validate -Payload . -ExpectedVersion 0.4.4
& .\windows-deploy.ps1 -Action Install -Payload . -WhatIf
```

手动安装/更新使用管理员终端执行 `-Action Install -Payload <解压目录> -RegisterService`。不要并发运行多个部署脚本。

自动恢复失败时：保留错误信息，停止服务；将相应 `.rollback-*` 中的程序文件逐一恢复到原程序目录；检查服务可执行路径及 `--data` 参数后再启动。不得用旧备份覆盖当前录像或未经核对的认证配置。

卸载会先停止并移除服务，再删除受管理的程序文件。配置、录像、旧程序备份及不认识的文件保留，程序目录可能因此仍存在。

## 发行验证与限制

发布前应完成：类型与自动测试、真实浏览器定位/跨段回归、载荷哈希校验，以及干净 Windows 虚拟机的首次安装、服务重启、版本升级、占用文件、启动失败回滚和卸载留数据检查。

当前工作机只生成和验证产物，不注册实际系统服务，不替换正在使用的安装。真实管理员安装、跨卷权限和系统重启场景必须在隔离虚拟机完成；不能把编译成功视为安装验收通过。安装包尚未进行代码签名，SHA-256 校验不能替代发行者签名。

打包工具可使用本机 NSIS，或用 `NAVORA_MAKENSIS` 指向其编译器。NSIS 官方下载入口：[NSIS 3.11](https://sourceforge.net/projects/nsis/files/NSIS%203/3.11/)。发行包中的 FFmpeg 和 ffprobe 遵循随包 GPLv3 许可，发布时同时提供对应构建的源代码获取方式与版本记录。
